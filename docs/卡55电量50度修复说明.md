# 卡 55% 电量 / 50°C 修复说明（v3.2.2）

## 现象
刷入去温控模块后重启，几秒内电量卡在 55%，温度卡在 50°C；卸载模块、清数据、降级都无效。

## 根因
去温控模块开机执行了：

```sh
echo "remove_temp_limit 1" > /sys/devices/platform/soc/soc:mca_business_charger/debug_ctrl
```

小米充电驱动 `mca_business_charger_comp` 收到该命令后：

1. 把 `remove_temp_limit=1` 持久化写进独立的 `charger` 分区（`/dev/block/sda22` 偏移 `0x1010`）。
2. 触发 `event=77`，内核线程把 `fake_soc` 写成 55、`fake_temp` 写成 500（即 50°C）。

`charger` 是 UFS 上的独立分区，不在 `/data`、`/system`、`/vendor`、`/boot`，所以恢复出厂、降级、卸载模块都不会清掉它。只要分区里还是 1，每次开机都会重新卡 55/50。

## 修复内容
1. 模块开机脚本不再写 `remove_temp_limit 1`，改为写 `remove_temp_limit 0`。
2. 已把手机当前 `charger` 分区 `0x1010` 写回 0，并清除当前假值 `fake_soc=-1`、`fake_temp=-999`。
3. 保留模块其它去温控功能，只移除了这一个会写坏电量/温度的开关。

## 验证结果
- `debug_ctrl` 当前输出：`remove_temp_limit 0`
- `charger` 分区 `0x1010`：`0`
- `fake_soc`：`-1`
- `fake_temp`：`-999`
- `dumpsys battery`：`level 46`，`temperature 353`（35.3°C）

## 注意
- 如果设备已经卡死 55/50，除了刷 v3.2.2，还需要按上面方式写回 `remove_temp_limit 0` 并清 `fake_soc`/`fake_temp`，否则重启后仍可能被旧分区残留触发。
- 不要再执行旧的 `remove_temp_limit 1` 写入，否则会再次把分区写坏。
